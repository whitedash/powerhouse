04

One look, both renderers

Embed .pw-err is canonical → Portal adopts it
The embed already has the right message treatment. resources/views/embed/form-widget.blade.php renders a per-field .pw-err node below each input (color: var(--pw-error); font-size: 12px; margin-top: 4px) and fills it from the server's 422 errors[field_key][0]. The Portal renderer adopts the identical treatment as .ffr-error. The only thing both add is the danger input border (the embed shows the message but no border today), so the input affordance matches too.

05

Interaction model the visuals represent

Validate on advance · block · save-later skips · submit validates all

What happens, when

Per-step validation runs at the step boundary; the whole-form check stays at the end.

Fill step 2
Click Next
Step 2 invalid → inline errors, stay on step 2
Step 2 clean → advance to step 3
  • Validation fires on advance (Next) — and only for the current step's fields (the fields with this step's form_step_id), never the whole form.
  • Failing fields show an inline error below the input (the treatment in §03); valid fields stay clean. Errors are keyed to the field, not a flat list.
  • Advance is blocked until the step is clean — the step index does not change while any current-step field is invalid.
  • Save-and-continue-later does NOT validate — it persists the current input as-is (drafts already save raw), so a respondent can leave with partial/invalid data and resume.
  • Back does not validate — moving to an earlier step is always allowed.
  • Final Submit validates the whole form — the existing end-of-form validation stays as the last gate (per-step is an earlier, friendlier catch, not a replacement).
Scope of this file: it pins the visual error state only. There is no conditional field visibility in forms today, so "skip hidden fields" is not depicted; if value-based show/hide is added later, the per-step check must skip hidden fields and the owning page (not FormFieldRenderer) must drive it. This is design-only — no renderer, controller, or validation code is changed here.
