Paragraphs and line breaks (<p>, <br>) come from the editor automatically and are also allowlisted. Anchor href is restricted to http / https / mailto; rel="nofollow noopener noreferrer" and target="_blank" are forced by the sanitiser (and set on the editor's Link extension to match). The editor offers no control outside this list, so nothing it produces is silently dropped on save.

No native dialogs. The existing RichTextEditor.vue uses window.prompt('URL:') for links/images — the project bans window.confirm/alert/prompt (all confirmations via ConfirmModal). This editor uses the inline popover above instead. An invalid / non-http(s)/mailto URL is rejected in the popover (so the user sees why), and is also dropped server-side as a second line of defence.

Build notes

Reuse what exists; restrict it to the allowlist
  • Foundation already exists. resources/js/Components/UI/RichTextEditor.vue is a working Tiptap editor (StarterKit + Link + Placeholder), used today only in Help. Build the form-builder editor from the same base rather than a new dependency — but a restricted variant (or a prop) so it can't emit non-allowlisted tags.
  • Trim StarterKit to the allowlist. Disable the marks/nodes the sanitiser strips anyway — heading, blockquote, code, codeBlock, strike, horizontalRule — and the Image extension. Keep paragraph, bold, italic, bulletList, orderedList, listItem, hardBreak, history.
  • Add underline. StarterKit has no underline; add @tiptap/extension-underline so → <u>.
  • Keep the Link config that already matches the sanitiser: openOnClick:false, HTMLAttributes:{ rel:'noopener noreferrer', target:'_blank' }. Validate the scheme (http/https/mailto) in the popover before setLink.
  • Replace the prompt-based link/image UI with the inline popover (§04). No window.prompt.
  • Drop it into the placeholder branch of the field-edit panel in resources/js/Pages/Internal/Forms/Index.vue, replacing the <textarea v-model="field.content">. Bind v-model="field.content"; the save path and server sanitiser are unchanged.
  • Styling is namespaced (e.g. wf-rte-* / scoped) and uses design tokens only — border/radius via classes (keeps audit:sections green); matches .slide-over-wide field rhythm.
07

Phase 2 — anticipated, not in the first build

Tables & images — each needs the hardened path extended first
Phase 2 · do NOT build in pass 1

Tables and images are planned additions

The first build ships the six controls above and nothing else. Tables and images are deliberately deferred: each adds tags that the entire render path currently strips, so they cannot be turned on at the toolbar alone — the allowlist, the renderer, and the embed widget must all be extended in lockstep, or the new markup silently disappears on save (and any gap becomes an XSS surface). Images carry an extra product + security decision on top.

Tablesnew tags
  • Sanitiser: extend FormContentSanitizer to allow table thead tbody tr th td (+ scope/colspan attrs as decided).
  • Renderer: add the same tags to FormFieldRenderer.vue's DOMPurify allowlist, plus table CSS.
  • Embed: confirm the widget renders tables and that the served (sanitised) markup matches.
  • Editor: add @tiptap/extension-table + cell controls (insert/delete row/col).
Imagesnew tag + decisions
  • Sanitiser / renderer / embed: allow <img> with a constrained src across all three points (as for tables).
  • Source model (open decision): upload via FileUploadService (stored, signed-URL served) vs external URL — drives storage, hosting, and CDN questions.
  • Security review: external src raises SSRF / pixel-tracking / mixed-content / arbitrary-host concerns; an upload path needs type + size limits via FileUploadService. The current Link extension already disabled base64 images for this reason.
  • Editor: add image insert UI (inline popover, not window.prompt) once the source model is chosen.
Rule of thumb for both: a control may not ship until its tag is allowlisted at every render point. The toolbar is the last thing to change, not the first — otherwise the sanitiser eats the output and the field looks broken.
